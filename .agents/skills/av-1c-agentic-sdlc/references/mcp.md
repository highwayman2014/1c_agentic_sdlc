# MCP для проекта и worktree

Общие профили: `bsl-reference`, `openviking`, `llm-wiki-personal`, `atlassian-mcp-server`.
Локальные профили: анализатор исходников и `llm-wiki-project`.

- Для справки платформы используй `bsl-reference`.
- Для кода и изменений используй workspace-профиль `bsl-analyzer` текущей рабочей папки.
- Для Confluence используй OpenViking с `target_uri="viking://resources/confluence-1c/"`.
- Для постановки используй Jira MCP.
- Для общих знаний используй персональную wiki.
- Для знаний проекта используй проектную wiki.

Готовые настройки находятся в `D:\repository\1c_agentic_sdlc\mcp`.
Перед применением прочитай `mcp/README.md` этого репозитория.
Используй `scripts/configure_mcp.py --workspace <фактический-путь> --check`.
Для применения используй `--apply-shared --apply`.
Для просмотра файлов используй `--output <каталог>`.
Для pi с pi-mcp-adapter используй `.pi/mcp-adapter.json` и `--client pi`.
Для Claude Code используй `.mcp.json` и `--client claude`.
Порядок подключения и готовые файлы описаны в `mcp/clients.md`.

В worktree анализатор должен читать его исходники.
Проектная wiki должна указывать на исходный проект.
Персональная wiki остаётся общей.
Используй общую установку анализатора через лаунчер.
Не закрепляй отдельную версию приложения для каждой задачи.
Не смешивай кеш worktree с кешем основной папки.
Не копируй ключи в настройки Git.

Codex читает `.codex/config.toml` доверенного проекта.
Файл `.mcp.json` сам по себе не подтверждает подключение в Codex.
После применения проверь фактические серверы, корни, обе wiki и статусы индексов.
Готовность лексики не подтверждает готовность семантики или графа.
При смене настроек проверь, не удерживает ли кеш прежний backend.
Наличие live-инструмента не разрешает работу в ИБ.
