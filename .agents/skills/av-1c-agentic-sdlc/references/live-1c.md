# Live-инструменты 1С через HTTP-расширение

## Выбери подключение

Используй единый MCP `bsl`.
При каждом live-вызове укажи `connection` из реестра подключений.
Не выбирай ИБ только по ветке, текущему проекту или имени worktree.
URL и имена переменных авторизации задаёт `mcp/onec-connections.json`.
Путь этого реестра задаёт `onec_connections` в runtime-конфиге.
Источники локальных учётных данных задаёт `onec_credential_sources`.
Проверь соответствие записи базы полям `database_id` и `expected_ref`.
Не используй учётные данные вложенного `repository`: они относятся к хранилищу.

Обёртка передаёт авторизацию через окружение процесса.
Не выводи секреты и не записывай их в MCP-конфиги, аргументы CLI или Git.
Worktree использует разрешённые подключения проекта без копирования секретов.
Если корпоративная сеть требует VPN, проверь его доступность.

`BSL_ONEC_CONNECTIONS_FILE` передаёт реестр официальному MCP-серверу.
Для `run/eval` нужны разрешение и `allow_execute=true` в выбранном подключении.
Наличие сервера или учётных данных не даёт разрешения на обращения к ИБ.

## Выбери инструмент

| Задача | Вызов | Ограничение |
|---|---|---|
| Прочитать применённые метаданные ИБ | `metadata tree/object`, `mode=infobase` | Это состояние ИБ, которое может отличаться от worktree. |
| Проверить SDBL платформой | `query validate` с `connection` | Различай блоки `platform`, `parser` и `workspace_semantics`. |
| Получить данные запросом SELECT | `query execute` с `connection` | Задай параметры и небольшой `limit`. Соблюдай разрешённый объём чтения. |
| Проверить BSL snippet | `execute check`, `input_kind=snippet` | Проверка синтаксиса не подтверждает поведение кода. |
| Проверить полноценный модуль | `execute check`, `input_kind=module` | Нужен отдельно настроенный `check_executor`, `module_type` и `context`. |
| Выполнить BSL или выражение | `execute run/eval` | Нужны явное разрешение и `allow_execute=true`; роль `BSL_ВыполнениеКода` в ИБ. |
| Прочитать ошибки выполнения | `event_log` с `connection` | Задай окно времени, уровень и `limit`; учитывай усечение выдачи. |
| Отлаживать выполнение | `debug` | Нужен отдельный debug endpoint и разрешение на воздействие на сеансы. |

`debug` использует протокол отладчика, а не HTTP-сервис расширения.
Для attach нужны `host`, `infobase` и debug port; по умолчанию порт 1550.
Успешный `/version` не подтверждает доступность отладчика.
Пути модулей и расширений должны соответствовать отлаживаемой копии.
После работы закрой подключение отладчика.

Для операций чтения HTTP-сервису нужна роль `BSL_ОсновнаяРоль`.
Она включает право `EventLog`, нужное для журнала регистрации.
Наличие административной учётной записи не разрешает агенту произвольные записи.
Установленное расширение не разрешает загрузку конфигурации или обновление БД.

## Учитывай источник и полноту

В `mode=infobase` используй имена коллекций платформы во множественном числе:
`Справочники`, `Документы`, `ОбщиеМодули`.
В `mode=source` используй типы анализатора в единственном числе: `Справочник`, `Документ`, `ОбщийМодуль`.
Не переноси эти значения между режимами без проверки контракта.

Пример чтения карточки из dev-базы:

```json
{"action":"object","mode":"infobase","connection":"dev","object_type":"ОбщиеМодули","object_name":"ОбщегоНазначения","max_output_tokens":1200}
```

Для `event_log` поле `contains` фильтрует уже выбранное окно из `limit` записей.
Пустой результат не доказывает отсутствие ошибки во всём журнале.
Для запросов используй `parameters`; не вставляй пользовательские значения в текст SDBL.
Учитывай `truncated`, `completeness` и `max_output_tokens`.

`execute check` не заменяет `diagnostics`, сборку EPF/ERF или проверку поведения в 1С.
Если snippet содержит объявление модуля, инструмент может вернуть `context_required`.
Если native executor отсутствует, проверка module возвращает unsupported.
Не скрывай такой отказ переходом к `run/eval`.

## Единое подключение

Справка, workspace и live-инструменты доступны через `bsl`.
Если найден TOML, сервер анализирует исходники этой рабочей папки.
Без TOML сервер использует пустой служебный источник.
В этом случае `graph`, `diagnostics` и `metadata mode=source` не описывают проект.
Статус поиска не подтверждает полноту overlay; см. [search-index.md](search-index.md).
Выбор рабочей папки не выбирает ИБ и не даёт разрешения на live-вызовы.
При каждом live-вызове укажи `connection`.

## Проверь совместимость

HTTP producer `1.2.0` и версия расширения в `Configuration.xml` — разные версии.
Для расширенных live-метаданных проверяй producer через `/version`.
При HTTP 401 сначала проверь выбранную ИБ, учётные данные и роли.
Не устраняй ошибку авторизации включением анонимного доступа.
