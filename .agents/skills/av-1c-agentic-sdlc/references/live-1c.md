# Live-инструменты 1С через HTTP-расширение

## Выбери подключение

В СММ настроен MCP `bsl-smm-live` для dev-копии `smm_auto_avasilyev`.
URL: `http://n01-1csql-stage:81/smm_auto_avasilyev/hs/bsl-analyzer`.
При каждом live-вызове указывай `connection="smm-auto-avasilyev"`.
Не выбирай ИБ только по текущей ветке или имени worktree.
Для корпоративной сети нужен Cisco VPN.

Общий реестр: `D:\repository\1c_agentic_sdlc\mcp\onec-connections.json`.
Источники учётных данных: `mcp/onec-credential-sources.json` рядом с реестром.
Для этой ИБ используется запись `id=dev`, `ref=smm_auto_avasilyev`
из `D:\repository\1c\smm_auto\.v8-project.json`.
Готовая копия реестра без учётных данных опубликована в
[mcp/configs/projects/smm_auto/.v8-project.json](https://github.com/highwayman2014/1c_agentic_sdlc/blob/main/mcp/configs/projects/smm_auto/.v8-project.json).
Она сохраняет настройки платформы, баз, расширений и адреса хранилищ.
Логины и пароли ИБ и хранилищ удалены на всех уровнях.
Worktree использует исходный локальный реестр; отдельная копия с секретами не нужна.
Не заменяй заполненный локальный реестр опубликованной копией автоматически.
После переноса на другой компьютер учётные данные заполняются только локально.

Обёртка читает только выбранные `user` и `password` в окружение процесса.
Не используй учётные данные вложенного `repository`: они относятся к хранилищу.
Не выводи секреты и не записывай их в MCP-конфиги, аргументы CLI или Git.

`BSL_ONEC_CONNECTIONS_FILE` передаёт реестр официальному MCP-серверу.
Значения авторизации передаются через `BSL_SMM_DEV_USER` и `BSL_SMM_DEV_PASSWORD`.
В реестре заданы только имена этих переменных.
Для `run/eval` установлено `allow_execute=false`.
Не меняй этот флаг без разрешённой задачи на выполнение BSL.

## Выбери инструмент

| Задача | Вызов | Ограничение |
|---|---|---|
| Прочитать применённые метаданные ИБ | `metadata tree/object`, `mode=infobase` | Это состояние ИБ, которое может отличаться от worktree. |
| Проверить SDBL платформой | `query validate` с `connection` | Различай блоки `platform`, `parser` и `workspace_semantics`. |
| Получить данные запросом SELECT | `query execute` с `connection` | Задай параметры и небольшой `limit`. Соблюдай разрешённый объём чтения. |
| Проверить BSL snippet | `execute check`, `input_kind=snippet` | Проверка синтаксиса не подтверждает поведение кода. |
| Проверить полноценный модуль | `execute check`, `input_kind=module` | Нужен отдельно настроенный `check_executor`, `module_type` и `context`. |
| Выполнить BSL или выражение | `execute run/eval` | Нужны явное разрешение и `allow_execute=true`; роль `BSL_ВыполнениеКода` в ИБ. |
| Прочитать ошибки выполнения | `event_log` с `connection` | Задай окно времени, уровень и `limit`; учитывай усечение выдачи. |
| Отлаживать выполнение | `debug` | Нужен отдельный debug endpoint и разрешение на воздействие на сеансы. |

`debug` в изученной 0.4.1 использует протокол отладчика, а не HTTP-сервис расширения.
Для attach нужны `host`, `infobase` и debug port; по умолчанию порт 1550.
Успешный `/version` не подтверждает доступность отладчика.
Пути модулей и расширений должны соответствовать отлаживаемой копии.
После работы закрой подключение отладчика.

Для операций чтения HTTP-сервису нужна роль `BSL_ОсновнаяРоль`.
Она включает право `EventLog`, нужное для журнала регистрации.
Наличие административной учётной записи не разрешает агенту произвольные записи.
Установленное расширение не разрешает загрузку конфигурации или обновление БД.

## Учитывай источник и полноту

В `mode=infobase` используй имена коллекций платформы во множественном числе:
`Справочники`, `Документы`, `ОбщиеМодули`.
В `mode=source` используй типы анализатора в единственном числе: `Справочник`, `Документ`, `ОбщийМодуль`.
Не переноси эти значения между режимами без проверки контракта.

Пример чтения карточки из dev-базы:

```json
{"action":"object","mode":"infobase","connection":"smm-auto-avasilyev","object_type":"ОбщиеМодули","object_name":"дм_ОбщегоНазначенияСМЗ","max_output_tokens":1200}
```

Для `event_log` поле `contains` фильтрует уже выбранное окно из `limit` записей.
Пустой результат не доказывает отсутствие ошибки во всём журнале.
Для запросов используй `parameters`; не вставляй пользовательские значения в текст SDBL.
Учитывай `truncated`, `completeness` и `max_output_tokens`.

`execute check` не заменяет `diagnostics`, сборку EPF/ERF или проверку поведения в 1С.
Если snippet содержит объявление модуля, инструмент может вернуть `context_required`.
Если native executor отсутствует, проверка module возвращает unsupported.
Не скрывай такой отказ переходом к `run/eval`.

## Работа при остановленном индексе

`bsl-smm-live` использует ту же общую установленную версию анализатора.
У него отдельный пустой служебный source-каталог и отдельный служебный кеш.
В окружении этого процесса отсутствуют настройки эмбеддингов и общего search baseline.
Он не читает CF и расширения основной папки или worktree.
Это технический профиль HTTP-инструментов; он не является индексом исходников.

Для статики используй профиль реального проекта после разрешённого запуска.
Не используй `search`, `graph`, `diagnostics` и `metadata mode=source` live-профиля
для выводов об исходниках проекта.
Локальный блок `query validate` здесь может сообщать неполноту метаданных.
Проверку платформой оценивай по отдельному блоку `platform`.

В нативном pi открыты `metadata`, `query`, `execute`, `event_log`.
Остальные инструменты этого технического профиля скрыты через `toolExposure`.
Для Codex и Claude Code соблюдай те же границы выбора инструментов.
Отладку с картой исходников на этом пустом профиле не настраивали.
Основной workspace СММ остаётся заблокированным по правилам [search-index.md](search-index.md).

Не устраняй ошибку авторизации включением анонимного доступа.
