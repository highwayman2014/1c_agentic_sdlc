# Проверяемое окружение: ветка и worktree

Используй этот порядок при создании, восстановлении и передаче рабочего окружения.
Пути общего репозитория, профили и разрешения бери из конфигурации проекта.

## 1. Сохрани исходное состояние

Проверь branch, HEAD, status и незавершенные Git-операции.
Проверь занятые ветки через worktree list.
Запиши базовый ref, SHA и путь документов задачи.
Для зависимой задачи используй явно согласованный родительский ref.
Перед переключением существующей ветки спланируй остановку backend выбранной папки.
В 0.4.3 горячее массовое checkout может потерять из индекса удаленный и восстановленный файл, даже при ready/complete.
Не оставляй backend наблюдать частично выполненный Git checkout.
Локальная remote-tracking ref не подтверждает актуальность сервера.

Обычная ветка использует исходники основной папки.
Worktree использует собственные исходники полного профиля.
Следуй [worktree.md](worktree.md) при создании отдельной папки.

Для основной папки общий helper используй так:

```text
python scripts/workspace_branch.py --workspace <основная-папка> --branch <существующая-ветка>
python scripts/workspace_branch.py --workspace <основная-папка> --branch <существующая-ветка> --apply --restart-backend
```

Первая команда только планирует. Вторая явно разрешает отключить клиентов выбранного собственного workspace до смены исходников.
Helper сохраняет кеши, отказывается от грязного дерева и чужого backend, не обновляет ветки с сервера.
После переключения переподключи MCP и проверь окружение на том же кеше.
В linked worktree используй проектный сценарий, чтобы не подменить манифест задачи.

Критерий: известны рабочая папка, ветка, база сравнения и место документов.

## 2. Определи доступный режим поиска

Для начального анализа используй общий baseline, если доступен разрешённый семантический режим.
Сопоставь снимок baseline с рабочей папкой по [search-index.md](search-index.md).
Для работы с текущими изменениями используй файлы и готовые подсистемы workspace.
Сохраняй существующие кеши. Анализатор использует отдельный изменяемый кеш для каждой папки.

Критерий готовности определяют инструменты, нужные для задачи. Семантический overlay и SQLite seed не требуются.

## 3. Проверь ресурсы и разрешения

Проверь общую установку анализатора и профиль MCP по [mcp-setup.md](mcp-setup.md#проверь-установку).
Оцени доступную память перед холодным запуском полного workspace.
Проверь уже работающие backend и их фактические корни.
Не запускай несколько холодных графов одновременно при нехватке памяти.
Порог памяти задается в runtime-конфиге для точного пути workspace.
При отказе admission сохрани индекс и освободи ресурсы перед переподключением.
Отказ по памяти не доказывает неисправность конфигурации или индекса.
Порог является политикой оператора, не минимальным требованием BSL.
Оценку памяти для холодного запуска не выдавай за необходимость нового выделения при подключении к уже проверенному warm backend.

Pi подключает все enabled MCP при открытии сессии.
Exposure codemode/deferred не отключает запуск сервера.
После восстановления нескольких вкладок учитывай суммарное потребление backend.

Проверь точное разрешение провайдера.
Разрешение одной рабочей папки не наследуется другой.
Платные запросы и фоновая генерация требуют согласованного объема действий.
При смене provider identity не оставляй два backend на одном изменяемом кеше.
Останавливай только установленный собственный процесс после проверки корня и режима.

Критерий: запуск укладывается в ресурсы и разрешенную политику.

## 4. Подключи и проверь реальные инструменты

Настрой единый bsl по [mcp.md](mcp.md).
При наличии проектного wrapper используй его.
Из общего репозитория проверка выполняется так:

```text
python scripts/workspace_health.py --workspace <папка> --wait 600
```

Добавляй --output только при явном запросе пользователя сохранить отчёт.
Команда может запустить workspace MCP и разрешенную политикой доиндексацию.
Это не безвредная проверка файлов конфигурации.
При необходимости используй `--lexical-only`.
Если задача требует проверки семантического режима, используй `--require-semantic`.
После разрешения расходов можешь добавить `--query <смысловой-запрос>`. Учитывай возможную фоновую генерацию.

Коды: 0 — запрошенные проверки готовы; 2 — прогрев или ограниченный режим; 1 — ошибка.
Инструмент не вызывает live 1C, не очищает кеш и не перезапускает backend.
При loading наблюдай progress и phase без перезапуска.
При failed исследуй причину; не увеличивай таймаут вместо исправления.
В 0.4.3 возможен transient native_failure до публикации движка: сохраняй исходный ответ.
Не переноси трактовку transient на ошибку уже опубликованного движка.

Дополнительно проверь справку, известный символ текущей ветки и его source/outline.
Проверь metadata в mode=source, diagnostics и graph/references в согласованном объеме.
Сверь фактические корни с рабочей папкой.
Пустой поиск не доказывает отсутствие символа при partial/stale или усечении.

Если проверяешь семантику, проверь режим [S] или [L+S], снимок baseline и полноту выдачи. Сверь результат с актуальным файлом.
После смены ветки проверяй оба направления: файл, существующий только на B, и файл только на A после возврата.
Одних контрольного метода, ready и общего числа чанков недостаточно.
В SQLite после удаления/восстановления проверь присутствие объявлений восстановленного файла в текущем индексе.
При установленной потере сделай управляемый холодный запуск на том же кеше; сначала останови только собственный backend.
Не исправляй это очисткой всех индексов или изменением исходников.
Если отчёт явно запрошен, его промежуточные записи держи вне дерева исходников.

## 5. Восстановись после сбоя

Сначала проверь фактическую ветку и сохраненный статус теста.
После перезагрузки заново устанавливай владельцев процессов; старые PID непригодны.
Проверь измененные текстовые файлы и SQLite в read-only режиме с учетом WAL.
quick_check по таймауту не является доказательством повреждения.
При повреждении сохрани файл и восстанови только установленную собственную версию.
При нехватке памяти не возобновляй все индексы одновременно.
Продолжай с сохранившихся векторов; не начинай полный пересчет автоматически.

## Результат

В state.md кратко укажи текущую готовность и открытые ограничения.
Если ресурс или сервис недоступен, явно укажи blocked/degraded и пригодные функции.
Подготовленные конфиги и запущенный процесс не означают полную готовность окружения.
