# Отчёт по кейсу: bsl → Vanessa MCP → скриншоты

Применяй при подготовке отчёта о runtime-проверке 1С со скриншотами.
Используй существующие данные успешного кейса. Не повторяй бизнес-операцию ради кадра.
Получай отдельное разрешение на новые записи, проведение, отправку и установку расширений.

## 1. Зафиксируй объём

В плане существующей задачи укажи критерии, выбранные dev-копии и список кадров.
Следуй составу документов проекта. Не создавай второй комплект планов.
Выбери каталог отчёта по разделу [«Подготовь документы»](../SKILL.md#подготовь-документы).
Для кейса используй `<каталог-задачи>/artifacts/<имя-проверки>/`.
Отделяй успешность обмена, создание документа, проведение и наличие движений.
Для каждой непроверенной части укажи ограничение.

Готовность: известны критерии и точные идентификаторы объектов, которые нужно показать.

## 2. Проверь инструменты и сеансы

1. Найди существующий клон Vanessa и прежние настройки. Читай auth-конфиги только с маскированием.
2. Проверь локальный commit, изменения и версию исполняемой EPF. Не сбрасывай чужой клон.
3. Сверь релиз и MCP-контракт с документацией upstream. Загружай новую EPF отдельно от прежней.
4. Запусти отдельный менеджер `/TestManager` в разрешённой ИБ. Используй приватный профиль без автозапуска сценариев.
5. Ограничь MCP loopback-адресом. Проверь `tools/list` и `get_environment_data`.
6. Подключи нужный профиль через `manage_test_client(action=connect, profileName=...)`.
7. Проверь фактическую готовность снимков через `get_window_list_os`.

`VanessaExt=true` в настройках не доказывает инициализацию компоненты.
Диалог установки в менеджере может оставить MCP доступным, но заблокировать инициализацию.
Сначала проверь стартовые окна менеджера. Подтверждай только ожидаемый диалог установки.
Если MCP ещё не управляет этим окном, допускается изолированный ручной bootstrap или явно ограниченная OS-операция по PID нашего менеджера.
Не добавляй такой bootstrap в бизнес-сценарий.

После инициализации компоненты клиент, запущенный ранее запасным путём, может иметь PID=0.
При отсутствии несохранённых изменений закрой только наш профиль через `close_test_client`.
Запусти его снова через MCP. Подтверди PID и список окон.
Не запускай второй экземпляр после таймаута вслепую. Сначала прочитай `get_vanessa_automation_state(format=json)` и состояние профиля.

Проверенный пилот 03.11.2026: Single 1.2.043.47, MCP 1.74, платформа 8.3.27.1936.
VAExtension 1.32 хватило для основного UI-прохода АС в пилоте.
`restart_vanessa` потребовал отсутствующую форму `VAExtension_ПерезапускVA`.
`get_event_log_test_client` по документации требует VAExtension не ниже 1.40.
Обновление расширения ИБ — отдельная доставка, а не автоматический способ исправления запуска.

Для pi используй нативный `.pi/mcp.json` или пользовательский `mcp.json`.
При новом сервере после внешнего изменения конфига нужен `/reload`.
Для уже зарегистрированного сервера применяй `/mcp reconnect <имя>`.
Если инструменты ещё не появились в текущей сессии, допустим явно отмеченный пилот через официальный Python MCP SDK и тот же Streamable HTTP endpoint.
Не называй такой пилот проверкой нативной экспозиции инструментов pi.

Готовность: известны версии, правильный профиль подключён, список OS-окон получен.

## 3. Получи навигационные ссылки через bsl

Для каждой ИБ явно задай `connection` и подтверди `СтрокаСоединенияИнформационнойБазы()`.
Ссылка e1cib сама не выбирает ИБ.
Свяжи `connection`, Ref ИБ и профиль Vanessa в карте окружения.

Для объектов используй платформенный `ПолучитьНавигационнуюСсылку(Ссылка)`.
Для записи регистра получи полный ключ: период и все измерения.
Создай ключ через менеджер регистра `СоздатьКлючЗаписи(СтруктураКлюча)`.
Передай его в `ПолучитьНавигационнуюСсылку`.
Проверь состав ключа по live-метаданным и значения — ограниченным SELECT.
Один UUID может соответствовать нескольким сообщениям разных периодов.

Пример формы выражения, а не готовый сценарий для произвольной ИБ:

```bsl
ПолучитьНавигационнуюСсылку(СсылкаНаДокумент)
ПолучитьНавигационнуюСсылку(МенеджерРегистра.СоздатьКлючЗаписи(СтруктураКлюча))
```

Открой каждую ссылку через `window_management(action=open_navigation, navigation_link=...)`.
Прочитай `get_active_window_data(type=navigation_link)`.
Сверь полный ключ или ref и поля формы с ожидаемым объектом.
Успешная генерация URI не доказывает, что ссылка откроется.
В пилоте ссылки на объект и ключи регистров открылись; ссылки на ячейку ТЧ с index=0 и index=1 были отвергнуты платформой.
В таком случае используй проверенную ссылку объекта и отдельный переход по таблице.
Отметь отказ точного перехода, вместо публикации неработающей ссылки как проверенной.

Готовность: карта содержит только проверенные открытием ссылки с владельцем-ИБ.

## 4. Сними доказательства через Vanessa MCP

1. Проверь профиль перед каждым переходом между ИБ.
2. Проверь существующие окна. `open_navigation` может открыть ещё одну форму того же объекта.
3. Если нужная форма уже открыта, активизируй её и сравни навигационную ссылку.
4. Получи дерево формы или Gherkin-состояние. Проверяй нужные значения, а не только заголовок.
5. Для таблицы используй `get_form_analysis(format=elements, only_table=...)`.
6. Активизируй нужную колонку через `manage_form_elements(action=activate_column, table_name=..., value=...)`.
7. Получи `get_window_list_os` и выбери точный заголовок OS-окна.
8. Сними цветной PNG через `get_window_screenshot_os(window_title=..., color_mode=color, file_name=...)`.
9. Открой полученный PNG инструментом просмотра. Проверь базу, объект, значения, видимость и отсутствие секретов.
10. Запиши время, SHA256, ссылку, окружение, наблюдаемые факты и ограничения кадра.

Окно формы и OS-окно — разные сущности.
У вкладки документа отдельного OS-окна может не быть: тогда снимай основное окно текущего TestClient.
У отдельной карточки регистра снимай её OS-окно.
При одинаковых заголовках не выбирай первое совпадение. Закрой только наши лишние немодифицированные формы или уточни выбор.

`window_management close/activate` в пилоте давал отказы на блокирующих отдельных формах.
Для закрытия известной немодифицированной карточки сработал Escape через Vanessa UI Automation после активации проверенного PID клиента.
Перед клавиатурным действием ещё раз проверь окно. При вопросе о записи или неожиданном обновлении остановись.
Кнопки «Записать», «Провести» и «Обновить» не нужны для снятия уже существующих данных.

Транспорт снимка может вернуть image-блок либо только путь к PNG на машине менеджера.
При втором варианте проверь файл и скопируй его в каталог отчёта без перекодирования.
Сохрани исходный SHA256. Не подменяй отсутствующий кадр сгенерированной картинкой.
Если для публикации нужен crop или маскирование, сохрани оригинал приватно и явно опиши преобразование.

Готовность: каждый опубликованный кадр просмотрен, ключ объекта подтверждён, видимые факты отделены от данных SELECT.

## 5. Собери и проверь отчёт

Используй `scripts/case_evidence_report.py` из каталога этого навыка.
Скрипт находится в `../scripts/` относительно этой справки.
Скрипт не обращается к ИБ или сети. Он проверяет манифест и строит переносимый offline HTML.

```bash
python <каталог-навыка>/scripts/case_evidence_report.py <каталог-отчёта>/manifest.json --check
python <каталог-навыка>/scripts/case_evidence_report.py <каталог-отчёта>/manifest.json
python -m unittest discover -s tests -p test_case_evidence_report.py -v
```

Манифест schema_version=1 содержит:
- `case_id`, `title`, `generated_at`, `verdict`, `scope`, `limitations`;
- `environments`: `id`, `name`, `ref`, `connection`, `profile`;
- `checks`: `title`, `status` (passed/limited/not_run), `evidence`;
- `links`: `id`, `label`, `environment`, `navigation_link`, `verified_open=true`;
- `screenshots`: `id`, `title`, `environment`, `link_id`, `path`, `sha256`, `captured_at`, `visual_review=passed`, `observations`;
- необязательные `toolchain` и `data_artifacts` (`path`, `label`).

До сборки подготовь manifest.json, navigation-links.json и screenshots/ внутри каталога отчёта.
В navigation-links.json сохрани проверенную карту из links манифеста.
Скрипт создаёт report.html; он не создаёт снимки или карту ссылок.
Включай в пакет только эти материалы и выбранные evidence-файлы.
Изображения и evidence используй по относительным путям внутри пакета.
Скрипт проверяет PNG, хеш, визуальную отметку, владельца-ИБ, проверенность ссылки и наличие файлов.
Это проверка комплекта, а не компьютерное зрение и не доказательство бизнес-корректности.

Разделяй источники: UI-кадр; запрос bsl; runtime-вызов; анализ исходников.
Кадр документа не доказывает отсутствие дублей, наличие движений или успешность прежнего события.
Приложи ограниченный SELECT и результаты повторов для этих утверждений.
Указывай, что кадры сняты позже бизнес-теста, если это так.

Не включай весь каталог tooling/ в ZIP. Он может содержать локальные пути, логи и auth-профили.
Не выводи список профилей, настройки с include_values или process command line без санитизации.
Vanessa может вернуть параметры профиля вместе с ошибкой: маскируй и успешные ответы, и исключения до вывода или записи.
Автоматическая проверка секретных ключей не заменяет ручной просмотр текста и изображений.

Готовность: проверки скрипта и unit-тесты успешны; отчёт открывается с локальными PNG; каждый вывод имеет источник; ограничения не скрыты.
Запиши пути отчёта, версии и результат в документы задачи.
