# Проверь настройку инструментов

## Подготовь проект

1. Задай пути сервисов и общей установки в `mcp/runtime.json`.
2. Добавь проект в `mcp/projects.json` с его ключом и `source`.
3. Укажи CF и расширения в `bsl-analyzer.toml` проекта.
4. Если нужен общий baseline, настрой его в TOML и `mcp/baselines.json`.
5. Если нужны live-инструменты, настрой реестр подключений и локальные источники учётных данных.
6. Примени настройки по [mcp.md](mcp.md).

Единое подключение используется по умолчанию.
Запись проекта с `unified=false` сохраняет прежние профили из `analyzers`.
Для нового проекта код генератора менять не требуется.
Пример минимальной записи: `mcp/examples/projects.json`.
Пример состава исходников: `mcp/examples/bsl-analyzer.toml`.
Файлы в `mcp/configs` содержат готовые примеры окружений.
Не копируй их абсолютные пути без сверки.

## Проверь установку

Общая обёртка использует app из установки лаунчера.
Если задан `broker_current`, она читает имя app из указателя версии.
Иначе используется `broker_application`.
Занятый stable app может отличаться от выбранной лаунчером версии.
Проверяй фактическую версию через MCP initialize.
Не закрепляй отдельную установку анализатора за каждой задачей.

Секреты храни в локальных env-файлах или реестрах вне Git.
Runtime-конфиг должен содержать пути и имена переменных, а не пароли.
Резервные копии настроек сохраняются вне рабочей папки проекта.
Не заменяй локальный реестр баз обезличенным примером.

## Проверь результат

До запуска выполни [проверку индекса](search-index.md).
Команды списка MCP могут запускать серверы и фоновую индексацию.

1. Проверь фактический список MCP клиента.
2. Проверь единственное подключение `bsl` и его рабочую папку.
3. Вызови `syntax_help` для проверки справки.
4. Проверь `search`, `graph`, `diagnostics` и `metadata` через `action=status`.
5. Проверь корни CF и расширений.
6. Проверь `unread_files`, freshness и completeness.
7. Выполни `search_code` и проверь полноту overlay.
8. Проверь проектную и персональную wiki.
9. Проверь нужные подключения документации и Jira.

Готовность лексики не подтверждает готовность семантики или графа.
`loading` при холодной сборке сам по себе не означает зависание.
Оцени прогресс, журналы и использование CPU.
При `failed` исследуй причину.
Не скрывай отказ повторными перезапусками или увеличением таймаута.
Наличие live-инструмента не разрешает обращения к ИБ.
