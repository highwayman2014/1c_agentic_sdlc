## Применить к текущему worktree СММ

Из `D:\repository\1c_agentic_sdlc` проверь компоненты и пути:

```powershell
python scripts/configure_mcp.py --workspace D:\repository\1c\worktrees\smm_auto\dev1c-33021-spisanie-tmc --check
```

Примени общие и локальные настройки:

```powershell
python scripts/configure_mcp.py --workspace D:\repository\1c\worktrees\smm_auto\dev1c-33021-spisanie-tmc --apply-shared --apply
```

Команда:

1. Определяет основную папку через Git common directory.
2. Сверяет её с `.worktree-task.json`, если манифест есть.
3. Создаёт нативный конфиг Codex и полный `.mcp.json`.
4. Сохраняет существующий отдельный кеш задачи.
5. Направляет проектную wiki в основную папку.
6. Переносит существующую авторизацию Atlassian из аргументов в локальный env-файл.
7. Сохраняет остальные серверы и политики инструментов.
8. Создаёт резервные копии изменённых файлов.

Скрипт не запускает серверы, индексацию, Git fetch и операции ИБ.
Если состав существующего анализатора неизвестен, скрипт останавливается до замены локальных настроек.
Для БП это существенно: старый нативный конфиг содержит девять профилей по организациям.
Готовый новый профиль `bsl-bp` берёт полный состав из действующего `.mcp.json`.
Выбор между этими составами требует отдельной сверки при миграции существующей папки БП.

Для другого зарегистрированного worktree передай его фактический путь в `--workspace`.
Для обычной ветки передай основную рабочую папку проекта.
Для просмотра файлов без применения используй `--output <каталог>`.
Он создаёт настройки Codex, Claude Code и pi. Для применения только pi или Claude Code
укажи соответственно `--client pi` или `--client claude`; `--client all` применяет все три.
Скрипт определяет СММ, КШР, ЗУП и БП по основной папке Git.
Для нового проекта сначала добавь его состав в [projects.json](https://github.com/highwayman2014/1c_agentic_sdlc/blob/main/mcp/projects.json).

## Общая установка и локальные секреты

[runtime.json](https://github.com/highwayman2014/1c_agentic_sdlc/blob/main/mcp/runtime.json) содержит общие пути, URL OpenViking и параметры эмбеддингов.
[projects.json](https://github.com/highwayman2014/1c_agentic_sdlc/blob/main/mcp/projects.json) содержит исходные папки и состав анализаторов.
Обновляй общую установку `bsl-analyzer` через установленный лаунчер.
Для broker обёртка использует общий `bsl-analyzer-app.exe`.
Путь задан в `runtime.json` как `broker_application`.
На Windows это сохраняет backend после закрытия клиента pi.
Версию приложения для каждого worktree не закрепляй.
Отдельными остаются исходники, изменяемые кеши и статусы рабочих папок.
Общий базовый индекс используется по [правилам индекса](search-index.md).
В СММ основной `bsl-analyzer.toml` и конфиг DEV1C-33021 подключают общий PostgreSQL baseline.
Генератор MCP сохраняет отдельный изменяемый кеш; source TOML задаёт общий снимок.
Проверка baseline и блокировка запуска описаны в [search-index.md](search-index.md).

Локальные файлы:

| Файл | Назначение |
|---|---|
| `C:\Users\shepa\.bsl-analyzer\embeddings.env` | `EMBEDDING_API_KEY`; при необходимости URL, модель и размерность |
| `C:\Users\shepa\.config\1c-agentic-sdlc\atlassian.env` | URL и авторизация Jira/Confluence |
| Переменная `NAPARNIK_TOKEN` | Авторизация `its_help` |

Скрипт использует уже заполненный файл эмбеддингов.
Публичные значения по умолчанию: текущий провайдер, `qwen/qwen3-embedding-8b`, размерность `1024`.
Пакет справки берётся из `C:\Users\shepa\.bsl-analyzer\platform-help\8.3.27.1936`.
Если пакет отсутствует, действует обычный механизм загрузки справки анализатора.
При первом `--apply-shared` скрипт сохраняет существующую авторизацию Atlassian в локальном файле.
Если локальный файл уже заполнен, его значения имеют приоритет.
После перевыпуска токена меняй только этот локальный файл.
Файлы env и резервные копии не должны попадать в Git.
Резервные копии создаются вне проектов: `C:\Users\shepa\.config\1c-agentic-sdlc\backups`.

Для намеренного лексического режима добавь `--lexical-only` перед `--` в вызов `mcp_profile.py`.
Готовые профили рассчитаны на семантический поиск с уже настроенным ключом.

## Проверить подключение

До команд ниже выполни [проверку базового индекса](search-index.md).
Команды списка MCP могут запускать серверы и фоновую индексацию.
Если повторное использование не подтверждено, не запускай workspace MCP.


1. Открой рабочую папку как доверенный проект Codex.
2. Выполни `codex mcp list` из этой папки.
3. Вызови `syntax_help` в `bsl-reference`.
4. Проверь `search`, `graph`, `diagnostics` и `metadata` через `action="status"` рабочего анализатора.
5. Проверь semantic target отдельно от lexical target.
6. Выполни `search_code` и проверь корни результатов и признаки неполной выдачи.
7. Вызови `wiki_status` и `wiki_recall` обеих wiki.
8. Выполни поиск OpenViking в указанном URI Confluence.
9. Получи нужную постановку Jira через Atlassian MCP.

При смене состава, эмбеддингов или пакета справки старый backend может удерживать кеш.
Сначала установи владельца кеша по журналу и PID.
При подтверждённом конфликте переподключи только backend нужного worktree.
Не удаляй кеш и не перезапускай все проекты подряд.
TTL broker в готовых профилях — 12 часов после отключения клиентов.
Это сохраняет прогретый процесс между чатами, но не устраняет холодный старт после перезагрузки Windows.
