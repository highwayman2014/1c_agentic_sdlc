# Изоляция задачи через worktree

Читай при подготовке, восстановлении и завершении окружения. Worktree изолирует файлы, но использует общий репозиторий Git: ветки, refs и часть настроек остаются общими.

## Выбор и подготовка

1. Установи корень исходного проекта и путь документов задачи. Прочитай применимые `AGENTS.md`, проектную инструкцию worktree и параметры wrapper-скрипта. Не переноси соглашения другого проекта по сходству имён.
2. Проверь `git status --short --branch`, `git worktree list --porcelain`, ветку задачи, локальную базовую ветку и upstream. Проверь незавершённые Git-операции через служебные пути Git: у linked worktree `.git` является файлом, поэтому проверка `.git/MERGE_HEAD` неверна.
3. Продолжай существующий worktree задачи после проверки состояния. Незакоммиченные правки исходной папки оставь на месте; не используй stash/reset и не переноси их автоматически.
4. Для новой ветки проверь требуемую проектом базу и сохрани исходный SHA. Совпадение с локальным remote-tracking ref не подтверждает актуальность сервера. Fetch выполняй в пределах разрешения проекта и пользователя. Если проверка сервера недоступна, укажи это явно.
5. Если требуется обновление основной ветки, соблюдай проектный порядок: чистое дерево, отсутствие незавершённых операций, согласованный SHA и только fast-forward. Не переключай занятую или грязную основную папку. При расхождении истории останови подготовку, не применяй reset/rebase.

## Создание

Используй проектный wrapper, если он есть, начиная с предварительной проверки. Не вызывай `git worktree add` в обход wrapper, который настраивает sparse-checkout, инструкции и инструменты. Если wrapper отсутствует, используй штатный Git-процесс по местным правилам; команды ниже не универсальны.

### Вариант с `scripts/task-git.ps1`

Только если текущие скрипт и инструкция подтверждают режимы, из исходного проекта выполни:

```powershell
powershell.exe -NoProfile -NonInteractive -File scripts/task-git.ps1 -Mode PlanWorktree -Task <slug> -TaskDirectory <существующий-путь-документов>
powershell.exe -NoProfile -NonInteractive -File scripts/task-git.ps1 -Mode StartWorktree -Task <slug> -TaskDirectory <существующий-путь-документов>
```

Для существующей ветки добавь `-ReuseBranch` в обе команды. Подставь проверенные аргументы; пути с пробелами заключай в кавычки. Имя ветки и каталог определяет wrapper. Не сбрасывай существующую ветку.

В пилоте СММ подробности находятся в `scripts/README-worktree.md`: ветки `task/<slug>`, документы остаются в исходном каталоге. Эти особенности не распространяются автоматически на другие проекты.

## Проверка новой папки

- Явно используй полученный абсолютный путь для последующих команд. Проверь ветку, HEAD и, при наличии, манифест подготовки.
- Проверь sparse-checkout, инструкции и профиль инструментов. Локальные настройки могут копироваться снимком без дальнейшей синхронизации. Документы веди в одном согласованном месте.
- Наличие `.mcp.json` или `.codex/config.toml` не подтверждает подключение клиента. Проверь реальный корень workspace анализатора и готовность нужных подсистем. При ошибке одной используй готовые с явным указанием ограничений. Не очищай кеш и не перестраивай индекс без установленной причины.
- Для wiki проверь принадлежность к исходному проекту. Не создавай копию проектной памяти для каждой задачи. Не выдавай индекс исходного checkout за индекс изменяемого worktree; использование RLM определяет проектный профиль.
- Создание worktree не назначает базу 1С. Не копируй auth-файлы, токены и подключения из основной папки.

Если подготовка оборвалась, проверь созданную папку, ветку и манифест. Сохрани результат и выясни причину; не удаляй их автоматически и не повторяй создание поверх существующего окружения.

## Доставка и закрытие

- Сравнивай результат с сохранённой базой задачи. Если основная ветка сдвинулась, не подменяй исходную базу молча. Для повторной доставки учитывай фактически поставленные коммиты.
- Не запускай старый `task-close.ps1` в linked worktree без подтверждённой поддержки. Обновление основной папки и завершение worktree — отдельные операции.
- После корпоративной выгрузки сверь содержимое изменённых объектов и сопутствующих файлов: разные SHA сами по себе не означают расхождение. Сохрани документы, отсутствующие в выгрузке.
- Перед разрешённым удалением проверь незакоммиченные и неотслеживаемые файлы, нужные ignored-файлы, коммиты и место сохранения документов. Принудительное удаление требует явного разрешения.
