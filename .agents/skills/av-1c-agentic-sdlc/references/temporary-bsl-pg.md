# Временный обход ошибок PG overlay

Статус: локальное исключение до приёмки официального релиза с нужными исправлениями.
Обычный запуск описан в [mcp-setup.md](mcp-setup.md#проверь-установку).
Этот файл содержит все специальные указания по доработанному exe.
После перехода на официальный релиз основной порядок SDLC не должен меняться.

## Когда применять

В исходном v0.4.3 выявлены две ошибки:

- [#810](https://github.com/itrous/bsl-analyzer/issues/810): фоновый прогрев использует интерактивный таймаут 12 секунд.
- [#811](https://github.com/itrous/bsl-analyzer/issues/811): частичный кеш в памяти скрывает сохранённые дисковые векторы.

Проверенная локальная сборка `bsl-analyzer-0.4.3-pg-bg2.exe` исправляет оба случая.
Она не является официальным релизом и не поставляется вместе с навыком.
Применяй её только для принятых рабочих папок по локальной конфигурации.
Текущее состояние issue не доказывает, что исправление уже вошло в установленный релиз.

Локальное исправление делает одну фоновую попытку с бюджетом 120 секунд без скрытых повторов.
Интерактивный поиск сохраняет бюджет 12 секунд.
Каждый фоновый проход объединяет точные дисковые ключи с кешем в памяти.
При совпадении ключа значение из памяти имеет приоритет.
Изменённый текст входа или graph_context может законно потребовать новый вектор.

## Выбери локальную сборку

В `mcp/runtime.json` задай `unified_workspace_applications`.
Ключ — точный абсолютный путь рабочей папки.
Значение — путь к одному общему проверенному exe.
Обёртка проверяет наличие файла до чтения учётных данных провайдера.
Если файл отсутствует, запуск завершается с ошибкой без подмены версии.

Фактический приоритет `unified_bsl.configure`:

1. `unified_workspace_applications` для точного пути рабочей папки.
2. `broker_current` для остальных папок.
3. `broker_application`, если указатель не задан.

Точное правило не наследуется другим worktree или дочерними папками.
Копирование TOML само по себе не назначает локальную сборку.
При создании нового worktree отдельно проверь это назначение.
Обёртка не собирает и не устанавливает exe.
Не меняй общий `current` ради проверки одной рабочей папки.

Сохрани исходный exe, патч, базовый commit и SHA-256 локальной сборки.
У локальной сборки номер в `initialize.version` может совпадать с официальным.
Поэтому проверяй путь фактического процесса и SHA-256 файла.
Перед сменой exe выполни обычный порядок остановки и переподключения из mcp-setup.
Одна запись в JSON не заменяет уже работающий брокер.

## Ограничь запросы

Необязательное точное правило `unified_workspace_embedding_max_request_bytes` задаёт положительное целое число байт JSON-запроса.
При разрешённом провайдере оно заменяет `EMBEDDING_MAX_REQUEST_BYTES` для выбранной папки.
В lexical-only режиме оно не включает провайдера.
Проверь, что лимит вмещает самый крупный одиночный вход.

Это лимит размера запроса, а не таймаут HTTP, MCP или вывода инструмента.
Назначение exe и лимита не отменяет политику baseline, разрешение расходов или порог памяти.
Локальные пути и учётные данные остаются вне Git.

## Проверь применение

Проверь реальные инструменты по mcp-setup.
Дополнительно проверь:

1. Локальный изменённый метод найден с `S` или `L+S` и `completeness=complete`.
2. Холодное переподключение без изменения точных входов не рассчитывает векторы документов повторно.
3. Создание, замена и удаление разрешённой тестовой фикстуры обновляют оверлей.
4. Локальная правка одной папки не появляется в другой.

Считай фоновые запросы, а не только рост таблицы кеша.
Повторная запись того же ключа может не увеличить число строк.
Вектор поискового запроса учитывается отдельно.

Локальная сборка не добавляет бесконечные повторы.
Настоящий сетевой отказ может оставить прогрев в failed до нового изменения или управляемого переподключения.
Одна попытка остаётся ограниченной 120 секундами.

## Верни официальный релиз

1. Проверь, что официальный релиз содержит исправления обоих issue.
2. Установи этот exe отдельно от принятой локальной сборки.
3. Согласуй проверку кандидата на выбранной рабочей папке.
4. Выполни те же проверки готовности, холодного переиспользования и изоляции на сохранённых данных.
5. После успешной приёмки выбери официальный релиз в общей установке.
6. Удали только относящиеся к обходу записи из `unified_workspace_applications`.
7. Если лимит размера запроса был временным, проверь штатный лимит и убери только соответствующее временное правило.
8. Переподключи MCP и проверь фактический официальный exe.

Проверь влияние общей установки на другие проекты до изменения указателя.
Сохрани рабочие baseline, namespace, правила памяти и разрешения провайдера.
Переход на официальный exe не требует очистки индексов или полного пересчёта корпуса.

Когда временных назначений больше нет, удали этот файл и единственную ссылку на него из mcp-setup.
Остальные файлы навыка не должны содержать специальных указаний по локальной сборке.
