# Базовый индекс и изменения рабочей папки

## Целевая схема

Решение пользователя от 30.10.2026: worktree используют индекс основного проекта.
Общий базовый индекс хранит сохранённые эмбеддинги проверенного снимка исходников.
Worktree читает базовый индекс и ведёт отдельный слой изменений — overlay.
Слой скрывает удалённые и заменённые фрагменты базового снимка.
Граф, диагностики и метаданные должны соответствовать исходникам worktree.
Общий базовый индекс не означает общий изменяемый SQLite-кеш.
Для обычной ветки в основной папке сохраняй существующий индекс проекта.

## До запуска анализатора

1. Найди сохранённый индекс основного проекта.
2. Учти SQLite, WAL и файлы векторного индекса.
3. Читай SQLite в режиме read-only; не запускай миграции для обследования.
4. Проверь число фрагментов и сохранённых векторов.
5. Проверь модель, размерность, формат входного текста и служебный профиль.
6. Определи снимок исходников или его проверяемый файловый манифест.
7. Сопоставь базовый снимок с рабочей папкой.
8. Проверь поддержку общего baseline установленной версией анализатора.
9. Запиши источник baseline, идентификатор снимка, слой изменений и ограничения в `state.md`.

Размер файла не доказывает полноту индекса.
Существование USEARCH не доказывает его совместимость с текущим SQLite.
Путь и SHA основной папки сегодня не доказывают, какой снимок был проиндексирован ранее.

Если способ повторного использования не подтверждён, не запускай workspace MCP.
Не используй список MCP как безвредную проверку: клиент может запустить серверы.
Наличие ключа API не разрешает повторную генерацию эмбеддингов всего корпуса.
Не очищай сохранённый индекс для устранения ошибки подключения.

## Во время задачи

Используй сохранённые векторы для совместимых фрагментов.
Проверяй весь вход эмбеддинга: модуль, вид фрагмента, имя, код и контекст графа.
Совпадения кода недостаточно, если изменился остальной вход.
Не подменяй свежесть worktree свежестью базового снимка.
Если индекс неполон, явно указывай границы семантического поиска.

Для новых или изменённых входов сначала определи объём недостающих эмбеддингов.
При запрете расходов не вызывай провайдера для заполнения этих пробелов.
Отдельно учитывай вызов эмбеддинга поискового запроса: полный индекс не делает этот вызов бесплатным.
Сохраняй уже оплаченные векторы при смене пути, клиента или версии анализатора.
При смене модели или формата сначала оцени совместимость и последствия.

## Обновление и завершение

После проверки корпоративной выгрузки обновляй общий baseline по порядку проекта.
Учитывай фактически изменённые входы; сохраняй совместимые векторы.
Новый baseline должен иметь проверяемый снимок и состояние готовности.
Не удаляй базовый индекс при завершении или удалении worktree.
Отдельный слой изменений удаляй только по разрешению и после проверки сохранности результата.

## Текущее ограничение bsl-analyzer 0.4.1

В изученном коде внешний общий baseline реализован через PostgreSQL.
Локальный SQLite workspace использует собственный индекс.
Ключ его кеша включает абсолютный путь проекта и топологию исходников.
Одинаковый `--cache-dir` не объединяет индексы разных worktree.
Штатное подключение прежнего SQLite как общего read-only baseline не подтверждено.

## Настроенное подключение СММ

Общий PostgreSQL baseline работает локально на `127.0.0.1:15432`.
Контейнер: `bsl-baseline-postgres`; данные: Docker volume `bsl-baseline-pg17`.
База: `bsl_baseline`; схема: `smm_auto`.
Выбранный снимок: `workspace-code:smm-auto-sqlite-g434948`.
Имя снимка ссылается на generation сохранённого индекса.
Исторический Git SHA неизвестен; не приписывай снимку текущий SHA основной папки.

Настройки находятся в `bsl-analyzer.toml` основной папки и DEV1C-33021.
Готовые копии этих файлов сохранены в `mcp/configs` общего репозитория.
У обеих папок один baseline и разные изменяемые кеши.
`mcp/baselines.json` хранит адрес, снимок и политику запуска.

Runtime получает роль `bsl_reader` через `scripts/baseline_credentials.py`.
Роль имеет только SELECT; запись в общий baseline ей не разрешена.
Пароли находятся в `D:\tools\bsl-baseline` вне Git.
Проверка сервиса: `python scripts/baseline_service.py`.
Применение настроек сервиса: `python scripts/baseline_service.py --apply`.
Команда не выполняет импорт и не вызывает провайдера эмбеддингов.

Перенос выполняет `scripts/bsl_baseline_import.rs` через штатный адаптер 0.4.1.
Он открывает SQLite read-only, учитывает WAL и переносит существующие документы и векторы.
Он не сканирует исходники, не создаёт embedder и не запрашивает новые эмбеддинги.
Проверку реального TOML и роли читателя выполняет `scripts/bsl_baseline_verify.rs`.
Она проверяет лексическую выдачу и семантическую выдачу по сохранённому вектору.
Это не проверка смыслового запроса с новой генерацией вектора.
Собранные утилиты и их SHA256 находятся в `D:\tools\bsl-baseline\tools`.
Для сборки помести исходники утилит в `crates/bsl-search/examples` исходников 0.4.1.
Используй `cargo build --offline -p bsl-search --example bsl_baseline_import --example bsl_baseline_verify --release`.
Это вспомогательные утилиты; общая установленная версия анализатора не заменяется.

Общая обёртка `scripts/mcp_profile.py` проверяет политику до запуска workspace.
Для основной папки СММ и всех её worktree задано `workspace_launch="paused"`.
Не меняй его на `enabled` до решения о расходах и проверки overlay.
Обычный старт с ключом провайдера может запустить эмбеддинги изменённых входов.
Готовность общего baseline не означает готовность и отсутствие расходов у overlay.

Отдельный HTTP-профиль `bsl-smm-live` описан в [live-1c.md](live-1c.md).
Он использует пустой служебный source-каталог без CF и без настроек эмбеддингов.
Его подключение не снимает блокировку индекса основного проекта и worktree.
