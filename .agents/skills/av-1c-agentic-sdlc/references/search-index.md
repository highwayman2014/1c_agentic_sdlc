# Базовый индекс и изменения рабочей папки

## Целевая схема

Worktree использует базовый индекс своего проекта.
Общий базовый индекс хранит сохранённые эмбеддинги проверенного снимка исходников.
Worktree читает базовый индекс и ведёт отдельный слой изменений — overlay.
Слой скрывает удалённые и заменённые фрагменты базового снимка.
Граф, диагностики и метаданные должны соответствовать исходникам worktree.
Общий базовый индекс не означает общий изменяемый SQLite-кеш.
Для обычной ветки в основной папке сохраняй существующий индекс проекта.

## До запуска анализатора

1. Найди сохранённый индекс основного проекта.
2. Учти SQLite, WAL и файлы векторного индекса.
3. Читай SQLite в режиме read-only; не запускай миграции для обследования.
4. Проверь число фрагментов и сохранённых векторов.
5. Проверь модель, размерность, формат входного текста и служебный профиль.
6. Определи снимок исходников или его проверяемый файловый манифест.
7. Сопоставь базовый снимок с рабочей папкой.
8. Проверь поддержку общего baseline установленной версией анализатора.
9. Запиши источник baseline, идентификатор снимка, слой изменений и ограничения в `state.md`.

Размер файла не доказывает полноту индекса.
Существование USEARCH не доказывает его совместимость с текущим SQLite.
Путь и SHA основной папки сегодня не доказывают, какой снимок был проиндексирован ранее.

Если способ повторного использования не подтверждён, не запускай workspace MCP.
Не используй список MCP как безвредную проверку: клиент может запустить серверы.
Наличие ключа API не разрешает повторную генерацию эмбеддингов всего корпуса.
Не очищай сохранённый индекс для устранения ошибки подключения.

## Во время задачи

Используй сохранённые векторы для совместимых фрагментов.
Проверяй весь вход эмбеддинга: модуль, вид фрагмента, имя, код и контекст графа.
Совпадения кода недостаточно, если изменился остальной вход.
Не подменяй свежесть worktree свежестью базового снимка.
Если индекс неполон, явно указывай границы семантического поиска.

Для новых или изменённых входов сначала определи объём недостающих эмбеддингов.
При запрете расходов не вызывай провайдера для заполнения этих пробелов.
Отдельно учитывай вызов эмбеддинга поискового запроса: полный индекс не делает этот вызов бесплатным.
Сохраняй уже оплаченные векторы при смене пути, клиента или версии анализатора.
При смене модели или формата сначала оцени совместимость и последствия.

## Обновление и завершение

После проверки корпоративной выгрузки обновляй общий baseline по порядку проекта.
Учитывай фактически изменённые входы; сохраняй совместимые векторы.
Новый baseline должен иметь проверяемый снимок и состояние готовности.
Не удаляй базовый индекс при завершении или удалении worktree.
Отдельный слой изменений удаляй только по разрешению и после проверки сохранности результата.

## Настрой общий baseline

Адрес сервиса, схему, снимок и credential helper задаёт `bsl-analyzer.toml`.
Источники учётных данных, `vault_role_base` и политику запуска задаёт `mcp/baselines.json`.
Параметры Docker-сервиса и список схем задаёт `mcp/baseline-service.json`.
Проверяй настроенную политику до запуска workspace.
Если запуск приостановлен, не обходи блокировку.
Точечные исключения рабочих папок задаёт `lexical_only_sources`.
Для новой рабочей папки проверь применимость разрешения проекта.
Не переноси исключения другой задачи автоматически.

Единая обёртка удаляет `EMBEDDING_*` и `BSL_MCP_EFFECTIVE_EMBEDDING_*`.
Она не читает приватный файл провайдера.
Общий каталог кешей задаёт `unified_cache` в runtime-конфиге.
Анализатор создаёт отдельный namespace по папке и составу исходников.
Общий каталог не означает общий изменяемый SQLite.
При смене подключения сохраняй прежние индексы и совместимые векторы.

Для настройки сервиса используй `scripts/baseline_service.py`.
Сначала выполни проверку без `--apply`.
Импорт и публикацию выполняй отдельно в разрешённом объёме.
Runtime-роль общего baseline должна иметь только права чтения.
Учётные данные не должны попадать в Git.

## Учитывай ограничения анализатора

Внешний общий baseline поддерживается через PostgreSQL.
Повторное использование локального SQLite как общего read-only baseline проверяй для установленной версии.
Размер кеша и одинаковый `--cache-dir` не доказывают повторное использование индекса.

В bsl-analyzer 0.4.3 начальная подготовка PostgreSQL overlay зависит от embedder.
Без него подготовка пропускается с причиной `no embedder configured`.
Поиск может вернуть baseline без текущих правок.
`search.status=ready` и нулевой локальный индекс не доказывают полноту overlay.
Проверяй freshness, completeness и причины index_building/stale_generation у search_code.
Не делай вывод об отсутствии кода по неполной выдаче.
Для изменённого кода используй готовые graph, metadata и diagnostics, разрешённый RLM или точечное чтение файлов.
Не включай провайдера для устранения ограничения без разрешения на расходы.
Проверяй ограничение заново при смене версии анализатора.
