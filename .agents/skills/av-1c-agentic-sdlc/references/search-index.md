# Семантический поиск по общему baseline

## Используй проверенный снимок

Для проекта используй один общий baseline. Он хранит векторы проверенного снимка CF и расширений из профиля проекта.
Используй семантический поиск главным образом в начале задачи, когда место реализации неизвестно.
Сверяй найденные фрагменты с актуальными файлами рабочей папки.

Перед использованием установи, какой commit или файловый манифест покрывает baseline.
Сопоставь снимок с HEAD и изменениями рабочей папки. Чистое дерево само по себе не подтверждает совпадение.
Если снимки различаются, используй выдачу для навигации. Укажи ограничения, которые влияют на выводы.
Текущий SHA основной папки сам по себе не подтверждает происхождение baseline.

Для проверки текущих изменений читай файлы рабочей папки. Используй точечный поиск и диагностики файлов.
Используй `references` и `graph`, если подтверждены их корень, актуальность и полнота.
Пустой результат поиска по снимку не доказывает отсутствие кода или связи в рабочей папке.
Семантический overlay, SQLite seed и подготовка layout не требуются для начала задачи или проверки правок.

## Проверь запуск и расходы

Перед запуском workspace проверь политику проекта. Даже команда списка MCP может запустить сервер и фоновую генерацию.
Если семантический режим не подтверждён, используй разрешённый лексический режим или другие доступные инструменты по [tools.md](tools.md).
Если запуск приостановлен, соблюдай блокировку.

По умолчанию единая обёртка отключает провайдера. Для точных путей из `embedding_sources` она может включить эмбеддинги запроса вместе с фоновой генерацией документов.
Считай оба вида вызовов расходами. Включай провайдера только после разрешения пользователя на возможный объём обоих видов вызовов.
Обёртка не гарантирует отдельный режим только для запросов.
Разрешение одной папки не действует для других. Пути `lexical_only_sources` работают без провайдера.
Наличие ключа API или готовых векторов не даёт разрешения на платный запрос или пересчёт.

Если проверяешь семантическую выдачу, проверь снимок, фактический режим, `freshness` и `completeness`.
`search.status=ready` сам по себе не подтверждает покрытие текущих файлов.
В 0.4.3 без embedder подготовка PostgreSQL overlay может пропускаться с причиной `no embedder configured`.
При `output_budget` сузь запрос или увеличь `max_output_tokens`. Учитывай усечение при оценке полноты.

## Обслуживай baseline по правилам проекта

Обновляй baseline после принятия изменений по порядку проекта. Фиксируй снимок и подтверждай покрытие CF и расширений.
Сохраняй оплаченные совместимые векторы. Перед пересчётом проверь модель, размерность и весь вход эмбеддинга, включая контекст графа.
При импорте проверь совместимость файловых отпечатков с runtime. Сохраняй исходные ключи и соответствие векторов их входам.
При смене модели или формата оцени объём недостающих векторов до разрешения расходов.
При ошибке подключения или смене версии сохраняй имеющийся индекс. SQLite обследуй в режиме read-only с учётом WAL и файлов векторного индекса.
Храни изменяемый SQLite отдельно для каждой рабочей папки. Частная копия SQLite имеет собственный снимок.
Сохраняй общий baseline при завершении задачи и удалении worktree.

Адрес сервиса PostgreSQL, схему, снимок и credential helper задаёт `bsl-analyzer.toml`.
Источники учётных данных и политику запуска задаёт `mcp/baselines.json`.
Соблюдай `blocked_embedding_snapshots` при импорте и генерации.
Параметры сервиса задаёт `mcp/baseline-service.json`.
При настройке сервиса сначала проверь план `scripts/baseline_service.py` без `--apply`.
Импорт и публикацию выполняй только в разрешённом объёме.
Выдай runtime-роли только права чтения общего baseline. Храни учётные данные вне Git.
