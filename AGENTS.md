# Правила проекта

Пиши кратко и ясно по принципам ASD-STE100: простые предложения,
одно действие на шаг, одинаковые термины. Сохраняй важные факты.

## Структура
- src/cf — основная конфигурация.
- src/cfe/<target> — расширения. Анализируй их вместе с основной конфигурацией.
- tasks/YYYY-MM/<ключ>-<имя> — документы задачи.
- src/epf и src/erf — исторические файлы. Не используй без указания пользователя.

## Документы задачи
Сначала найди каталог по ключу Jira. Не создавай дубли.
Имя каталога задачи:
1. идентификатор Jira, пример DEV1C-12345 
2. краткое наименование задачи на русском языке
- description.md — полная постановка Jira: формулировки, структура,
  ссылки и URL задачи. Не добавляй решения.
- plan.md — решения, шаги реализации и проверки.
- state.md — текущий этап, выполненные шаги, следующий шаг,
  открытые вопросы и результаты проверок. Без истории действий.
Другие документы создавай только при необходимости.

## Подготовка к выполнению задачи
1. Актуализируй локальный main из удаленного репозитория
2. Создай новую git ветку для задачи 

## Анализ
1. Получи задачу через Atlassian MCP. Сохрани постановку в description.md.
2. Исследуй код через bsl-analyzer. Используй cc-1c-skills по задаче.
3. Выяви пробелы и противоречия. Существенные вопросы задай пользователю.
4. Запиши решения в plan.md. Укажи источник согласованных уточнений.
5. Для каждого шага укажи требование, файлы, изменение и критерий готовности.
6. Обнови state.md для передачи исполнителю. На этапе анализа код не меняй.

## Разработка
1. Прочитай description.md, plan.md и state.md.
2. Выполняй план по шагам. Не расширяй требования.
3. При противоречии останови затронутый шаг и запиши вопрос в state.md.
4. Проверь diff, диагностики и изменённые запросы. XML проверяй через skills.
5. Обнови state.md: что готово, что осталось, какие проверки выполнены.

## Ревью
Для сложных решений или спорных изменений вернись к более сильной модели.
Проверь соответствие постановке и плану. Замечания внеси в state.md.
Статический анализ не заменяет запуск 1С. Укажи невыполненные проверки.

## Границы
Не меняй чужие файлы вне задачи. Не выводи секреты.
Push, загрузку в ИБ и помещение в хранилище выполняй только по разрешению.
